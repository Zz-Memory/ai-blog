# 8 系统测试

## 8.1 测试目的

系统测试是软件开发生命周期中的重要阶段，其核心任务是在接近真实运行环境的条件下，对系统的功能正确性、运行稳定性、交互可用性以及基础安全性进行全面验证。对于本项目“AI Blog 智能博客系统”而言，系统测试不仅用于确认系统是否满足需求分析与总体设计阶段提出的功能要求，还用于检查系统在实际使用场景中的响应速度、异常处理能力与权限控制效果。

由于博客类系统涉及文章展示、文章搜索、用户登录、收藏互动、后台管理等多个模块，因此测试工作不能仅停留在“功能是否能用”的层面，还应进一步验证各功能在边界输入、异常输入、重复操作以及不同权限角色下的表现是否符合预期。通过系统测试，可以发现开发阶段难以完全暴露的问题，并为系统最终交付和论文撰写提供依据。

本章主要从以下三个层面展开：

1. **功能测试**：验证各核心业务模块是否满足设计要求；
2. **性能测试**：验证系统在正常访问和一定压力下的响应能力与稳定性；
3. **安全测试**：验证系统对未授权访问、参数篡改与异常输入的防护能力。

## 8.2 测试环境与测试方法

### 8.2.1 测试环境

为了保证测试结果具有参考价值，本项目在与开发环境较为接近的条件下完成系统测试。测试环境如下：

- 操作系统：Windows 10/11
- 浏览器：Microsoft Edge、Google Chrome
- 前端框架：Next.js、TypeScript
- 后端接口：基于项目实际实现的 API 路由
- 数据库：MySQL（或项目实际部署所使用的数据库）
- 测试工具：浏览器开发者工具、接口调试工具、页面刷新与交互测试、简单压力访问模拟

### 8.2.2 测试方法

本项目主要采用黑盒测试方法，对用户可见功能进行输入输出验证；同时结合接口返回结果和数据库数据变化情况，对关键流程进行辅助检查。测试时重点关注以下几点：

- 功能是否能够正常完成；
- 页面跳转、数据展示、状态切换是否正确；
- 错误输入或空值输入时系统是否具有合理提示；
- 未登录或无权限用户是否能够访问受限资源；
- 系统在连续操作与并发访问时是否存在明显卡顿或错误。

测试结果采用“测试说明 + 测试效果图描述 + 测试结果分析 + 测试表格”的方式呈现，以便论文表达更清晰，也更符合毕业设计论文的写作规范。

## 8.3 功能测试

功能测试用于验证系统各模块是否能够按照需求正常运行。AI Blog 智能博客系统的核心业务流程主要包括用户登录、文章浏览、文章详情查看、文章搜索、收藏与取消收藏、后台文章管理等。以下对主要功能分别进行测试说明。

### 8.3.1 用户登录功能测试

用户登录是系统的入口功能，也是后续权限控制的基础。登录模块不仅要判断账号密码是否正确，还要检查空值输入、错误账号、错误密码、重复提交等情况是否能够得到合理处理。

**测试目的：** 验证用户在输入正确账号信息时能够成功登录，输入错误或为空时系统能够给出明确提示，并保证不会出现越权登录或页面异常。

**测试前提：** 系统中已存在一个状态正常的测试账号。

**测试说明：**

1. 打开登录页面，输入正确的用户名和密码；
2. 输入错误密码进行登录；
3. 输入不存在的用户名进行登录；
4. 不输入账号或密码直接提交；
5. 观察登录结果、页面跳转与提示信息。

**测试结果分析：**

当输入正确的账号信息时，系统能够正常完成身份认证，并将用户状态写入会话或令牌中，随后跳转至首页或个人中心页面；当输入错误密码或不存在的账号时，系统会返回“账号或密码错误”之类的提示，不会暴露具体账号状态，也不会进入系统内部页面。对于空值提交，前端基础校验能够阻止无效请求提交。整体来看，登录功能符合预期。

**测试目的：** 验证用户能够使用合法信息成功注册账号，且对空值、重复用户名、密码不一致等情况能够做出正确反馈。

**测试前提：** 系统允许新用户注册，且不存在重复测试账号。

**测试说明：**

1. 进入注册页面，输入符合规则的用户名和密码；

3. 输入两次不一致的密码；
4. 不填写必填项直接提交；

**测试结果分析：**

系统能够正确识别合法注册信息，并将新账号写入数据库。重复用户名时系统会明确提示该用户名已存在，避免重复数据插入；密码不一致时页面会提示两次密码输入不一致，防止用户因输入错误导致注册失败。整体注册流程稳定，符合系统设计要求。

## 8.5 安全测试

安全测试用于验证系统是否具备基础的访问控制能力、参数校验能力和异常输入处理能力。虽然本项目属于毕业设计性质的中小型系统，但由于涉及用户身份认证与数据写入操作，仍然需要对常见的安全风险进行基本验证。

### 8.5.1 登录鉴权安全测试
