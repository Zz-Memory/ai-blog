第2章  相关技术与理论基础

2.1  Next.js 简介
Next.js 是基于 React 的前端开发框架，由 Vercel 推出并持续维护。它在 React 组件化开发模式的基础上，进一步提供了更加完善的工程化能力，包括路由系统、服务端渲染（SSR）、静态站点生成（SSG）、增量静态再生（ISR）、接口路由、图片优化以及构建优化等功能。相比于传统单页应用框架，Next.js 更加适合构建既需要良好交互体验，又需要较高首屏性能和搜索引擎友好性的 Web 应用。

Next.js 的核心特点主要体现在以下几个方面。
(1) 路由机制清晰。Next.js 采用文件系统路由，页面文件的位置决定访问路径，开发者无需手动配置复杂路由表即可快速构建多页面应用。
(2) 支持多种渲染方式。Next.js 既支持在服务端预渲染页面，也支持在构建阶段生成静态页面，还支持按需再生页面内容，能够根据业务场景灵活选择不同渲染策略。
(3) 全栈开发能力较强。Next.js 内置 API Route 能力，可在同一项目中同时完成前端页面与后端接口的开发，减少前后端协作成本。
(4) 性能优化能力突出。Next.js 在代码分割、资源预加载、图片处理、缓存控制等方面提供了较完善的支持，有助于提升页面加载速度和用户体验。
(5) 生态成熟。作为 React 体系中应用广泛的框架，Next.js 能较好地与 TypeScript、状态管理工具、CSS 框架以及各种第三方服务集成。

2.2  Prisma 简介
Prisma 是一款现代化的数据库访问与 ORM 工具，广泛用于 TypeScript 与 JavaScript 生态中。它通过类型安全的方式连接应用程序与数据库，能够将数据库表结构映射为开发语言中的模型对象，从而简化数据库操作。与传统 SQL 直接编写方式相比，Prisma 更注重开发体验、类型提示和可维护性，能够有效降低数据库访问过程中的错误率。

Prisma 具有以下主要特点。
(1) 类型安全。Prisma Client 基于数据库模型自动生成类型定义，在代码编写阶段即可得到清晰的类型提示，减少字段名拼写错误和参数类型错误。
(2) 数据模型集中管理。Prisma 使用 schema 文件描述数据库表结构、字段类型、关联关系和索引信息，使数据库结构定义更加直观统一。
(3) 查询语法简洁。Prisma 提供链式 API 和对象式查询写法，常见的增删改查操作可以使用较少代码完成，同时保持较高可读性。
(4) 支持复杂关系映射。Prisma 能够处理一对一、一对多、多对多等关系模型，适用于具有较多实体关联的业务系统。
(5) 迁移能力完善。Prisma 自带数据库迁移机制，便于在开发、测试和部署过程中同步数据库结构变更。

2.3  PostgreSQL 数据库简介
PostgreSQL 是一种功能强大、开源的对象关系型数据库管理系统，具有较高的稳定性、扩展性和标准兼容性。它遵循 SQL 标准，同时提供丰富的数据类型、复杂查询能力、事务支持以及良好的并发控制机制，因此常被用于对数据一致性、可靠性和扩展能力要求较高的系统中。

PostgreSQL 的主要特征如下。
(1) 数据完整性高。PostgreSQL 支持主键、外键、唯一约束、检查约束等多种完整性约束机制，能够保证数据在结构层面的正确性。
(2) 事务支持完善。PostgreSQL 提供 ACID 事务特性，能够在多步骤数据操作中保持一致性，适合博客系统中涉及文章、评论、通知等多表联动场景。
(3) 并发控制能力强。PostgreSQL 采用多版本并发控制（MVCC）机制，能够在高并发场景下兼顾读取性能与写入稳定性。
(4) 扩展能力丰富。PostgreSQL 支持视图、索引、存储过程、自定义函数、触发器等功能，可满足复杂业务的数据处理需求。
(5) 查询能力灵活。PostgreSQL 对复杂条件查询、聚合分析、关联查询具有良好的支持，适用于对内容、用户行为与互动数据进行检索和统计分析。

2.4  AI 大模型 API 简介
AI 大模型 API 是指通过网络接口方式，将大语言模型能力以服务形式提供给应用程序调用的技术。开发者无需直接部署和训练模型，只需按照接口规范向服务端发送请求，即可获得文本生成、内容理解、问答对话、文本润色、摘要提取等智能能力。当前常见的大模型 API 通常具备统一的请求格式、返回格式以及流式输出机制，便于集成到各类 Web 应用中。

AI 大模型 API 的主要特点包括以下几个方面。
(1) 自然语言理解与生成能力强。大模型能够根据上下文进行语义理解，并生成连贯、自然的文本内容。
(2) 支持多种应用场景。大模型 API 可用于智能问答、内容生成、文本改写、摘要提取、信息抽取、对话交互等多种场景。
(3) 调用方式灵活。大模型 API 一般支持 HTTP 请求调用，开发者可根据需要设置模型名称、提示词、上下文消息、温度参数以及输出格式等。
(4) 适合流式响应。许多大模型 API 支持边生成边返回的流式输出方式，能够提升交互体验，减少用户等待感。
(5) 具有较强的扩展性。通过合理设计提示词和上下文结构，AI 大模型 API 可与不同业务系统结合，形成智能助手、辅助创作、知识问答等能力模块。

2.5  B/S 架构简介
B/S 架构，即 Browser/Server 架构，是一种以浏览器作为客户端、以服务器作为核心处理中心的软件体系结构。用户只需通过浏览器访问系统，无需在本地安装专用软件，即可完成业务操作。系统的主要逻辑、数据处理和资源管理通常集中部署在服务器端，由服务器统一提供页面内容、接口服务与数据访问能力。

B/S 架构的主要特点如下。
(1) 使用方便。用户通过浏览器即可访问系统，部署门槛低，适合跨平台访问。
(2) 维护成本较低。系统升级和功能迭代主要在服务器端完成，客户端无需频繁安装更新。
(3) 共享性较强。多用户可通过网络同时访问统一平台，便于集中管理数据与业务流程。
(4) 跨平台能力好。只要终端具备现代浏览器即可访问系统，兼容不同操作系统和设备。
(5) 易于扩展。随着业务增长，可以通过增加服务器资源、拆分服务模块等方式提升系统承载能力。

B/S 架构已经成为现代 Web 系统的主流架构形式之一，特别适用于内容管理、在线协作、信息发布和智能交互类系统。
